# Per-principal read scoping (MAR-90), design as approved

Fork-only. Approved by the watchman on 2026-11-09 for the next rally; nothing here is built yet.
It closes the "reads aren't scoped" gap in [threat-model.md](threat-model.md).

## The problem

`SessionBinding` (MAR-80) governs what a connection may write and act as, not what it may read.
`GetAllMessages`, `GetAllMessageReads`, `GetAllMessageOffers`, and the macro-generated by-ids
queries for those three entities give every valid principal every inbox. myko#129's subscription
hook (`subscription_authorization.rs`) allows, drops or errors a whole subscription, never single
items, so scoping is Marshal's to do.

The shim's Codex bridge (`crates/shim/src/codex_bridge.rs`) subscribes to `GetAllMessages` and
`GetAllMessageReads` and filters client-side for its own threads
(`unread_local_codex_sessions`), so on a paired machine running Codex those two can't simply be
refused.

## The design

1. **Two caller-scoped queries in entities**, `GetMessagesForCaller` and
   `GetMessageReadsForCaller` (`#[myko_query(Message)]` / `#[myko_query(MessageRead)]` with a
   `test_entity` predicate; `build_view` left to the default, which filters the store by the
   predicate). The predicate reads the request's auth (`ctx.query_context.req.auth`) and asks an
   installed hook for the caller's owned sessions; the daemon installs it from
   `SessionBinding`'s table (`marshal_entities::scope::install_owned_sessions`). With no auth the
   predicate is true, so plain mode is unchanged. A message passes when its `to_session_id` or
   `from_session_id` is the caller's, or it's a room message and any of the caller's sessions is a
   `RoomMember` of that room (a scan of the `RoomMember` store per test). A read passes when its
   `session_id` is the caller's. A released session's mail drops out of the caller's view at
   release, which is the intended direction (watchman's note b). A membership change doesn't
   retro-include older room messages in a live view; accepted.
2. **The bridge subscribes to the scoped queries** instead; its filtering stays as it is.
3. **`MARSHAL_SCOPED_READS=1`** (startup-only; note d: flipping it at runtime isn't expected, and a
   test says so) makes `SessionBinding` refuse, to any principal but the local one, `Execute`
   requests for `GetAllMessages`, `GetAllMessageReads`, `GetAllMessageOffers`, `GetMessagesByIds`,
   `GetMessageReadsByIds` and `GetMessageOffersByIds` (note a: every read path over the three
   per-session mail entities). The TUI and web UI run on the host and keep them.
4. **`GetAllSessions` stays open** to every principal: the roster is what `tell` and the bridge
   need, and muster accepted the same. The threat model's gap entry narrows rather than closes:
   roster rows carry `cwd`, `current_task` and host of every machine (note c).

## Tests to write

- `session_binding`: under the flag the six queries are Forbidden for a paired principal and
  allowed for the local one; without the flag all are allowed.
- In-process (daemon tests): a `CommandContext` carrying a real `AuthSession` from
  `PairingAuthenticator`; with laptop owning `s1`, `GetMessagesForCaller` returns only `s1`'s mail
  (direct and room), `GetMessageReadsForCaller` only `s1`'s reads, and with no auth both return
  everything.
- `tls_e2e`: a raw WebSocket `ws:m:query` for `GetAllMessages` with a paired token under the flag
  gets `ws:m:query-error` "permission denied"; with the local token it's answered.
- A test that the flag is read at startup only.
